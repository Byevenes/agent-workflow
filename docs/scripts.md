# Scripts

Scripts carry no comments (decision 20: only issue or RFC links and license lines are allowed). What each one does:

- `scripts/link.sh`: points the user-level Cursor and OpenCode folders at this repo, removes old route-work links that point here, and sets `core.hooksPath` to `.githooks`. It also keeps relative symlinks in `.cursor/agents/` for `zigl`, `zninja`, and `zsensei` (`../../agents/<name>.md`), which Cursor CLI and Cloud Agents load (issue #58). It never replaces a regular file; directories under `~/.agents/skills` are added only when the name is absent. It copies `zigl`, `zninja`, and `zsensei` into `~/.cursor/plugins/local/zstack-agents/agents/` as regular files, after removing a symlink at that destination so the copy does not follow it, and it writes `.cursor-plugin/plugin.json` with name `zstack-agents` and `"agents": "./agents/"`. Matt skills under `~/.agents/skills` are mirrored into Cursor and OpenCode; pstack skills from the Cursor plugin cache go into OpenCode, as `pstack-<name>` when the plain name is taken. `skills/versions` lists one skill name and one rev on each line. `scripts/link.sh` respects a tag or a commit. When a skill has no line, or its rev is `main` or `HEAD`, that skill follows the checkout. To return to main, delete the line or set the rev to `main` or `HEAD`, then run `scripts/link.sh` again. The clone must contain the pinned commits. A depth-1 clone cannot resolve them.
- `scripts/setup-check.sh`: reports whether the local setup resolves, whether the `zgrill`, `zspec` and `ztickets` wrappers and Matt's skills they read are present, whether `tdd` is model-invocable, and the optional MCP env vars (not failures). It fails when a project agent under `.cursor/agents/` is missing, is not a relative symlink to `../../agents/<name>.md`, or does not resolve. It fails when the zstack-agents plugin manifest is missing or lacks `"name": "zstack-agents"` and `"agents": "./agents/"`, and when one of those three plugin agent files is missing, is a symlink, or differs from `agents/<name>.md`. Never prints secret values. For each git repo under the clients root it appends the local artifact lines `.scratch/` and `.atl/` to that repo's `info/exclude` when the exact line is missing, creates the file when it is absent, leaves every other line in place, and is safe to run again. The `local-exclude` line counts repos that have both entries. It does not edit `.gitignore`, add a tracked config file, or install a hook. `scripts/setup-check.sh --help` and a normal run both point at `docs/security-scan.md`. That playbook is the client path (scanner on the developer machine) and the personal path (gitleaks in CI for this repo). A normal run also prints `gitleaks: present` when the binary is on PATH, or a warn when it is missing; that line never fails the script and never installs anything. The script does not install a scanner or a hook.
- `scripts/route-audit.sh [project-filter] [days]`: retro counts from Cursor transcripts under `~/.cursor/projects` (zstack or route-work invoked, zninja or implementer launched, poteto-mode loaded by zninja, inline edits with and without a stated reason). Counts only.
- `scripts/retro-log.sh`: records each applied retro change in `.scratch/retro-log.tsv`. Columns are id, date, state, cksum, bytes, error, and path. `begin --path <rel>` saves the current bytes under `.scratch/retro-open/<id>`, or writes a `<id>.missing` marker when the path is absent, and prints the new id. `seal <id> --error <text>` requires that open id, rejects an empty error, records the POSIX `cksum` of the file, and appends a pendiente row. A missing file at seal time stores the fingerprint word `missing` and byte count 0. Seal moves the saved bytes to `.scratch/retro-snapshots/<id>`. `pending` prints pendiente rows with no header and exits 0 when none exist. `confirm <id>` moves a pendiente row to confirmado, deletes the snapshot, and prints the id. A second confirm exits non-zero and leaves the row unchanged. `revert <id>` moves a pendiente row to revertido and prints the id. It prints `restored` and copies the saved bytes back when the current fingerprint still matches, or deletes the path when the retro added the file. It prints `marked-only` and does not change the tree when the snapshot is gone. A different fingerprint prints `dirty`, exits 3, and leaves the row pendiente. `revert --force <id>` restores even when the fingerprint differs. Exit 2 is usage, a bad field, or a rejected path. Rejected paths include an absolute path, a leading tilde, a backslash, an empty segment, `.`, `..`, and any path under `.scratch`. A tab or a newline in any field is also exit 2. `RETRO_ROOT` selects the worktree and defaults to `git rev-parse --show-toplevel`, or to the current directory when that fails. `RETRO_DATE` sets the row date as `YYYY-MM-DD`.
- `scripts/run-log.sh`: appends each run to `$RUN_ROOT/.scratch/run-log.tsv` and does not rewrite earlier rows. The script creates that file on the first successful append. `RUN_ROOT` selects the worktree and defaults to `git rev-parse --show-toplevel`, or to the current directory when that fails. Columns are id, task, model, checks, result, and cost. `append --task <text> --model <text> --checks <text> --result <text> --cost <text>` takes those flags in that order, requires every value to be non-empty, and prints the new id. `show` prints every row with no header and exits 0 when the log is absent. `show <id>` prints that one row. A reader uses `show` to get the model, the checks that passed, and the cost. Exit 2 is usage, a bad id, or a tab or a newline in a field. An unknown id exits 1. This log is separate from `scripts/retro-log.sh`.
- `scripts/mcp-gitlab.sh`, `scripts/mcp-postgres.sh`: start those MCP servers; the token or URL stays in the environment.
- `scripts/check-delivery-note.sh <note>`: exits 0 when a client delivery note has no internal mention, and exits 1 when it does. Patterns, case-insensitive: tool and agent names (`zstack`, `zninja`, `zsensei`, `zigl`, `zgrill`, `zspec`, `ztickets`, `zretro`, `poteto-mode`, `poteto`, `opencode`, `obsidian`, `agent-workflow`), model prefixes (`grok-`, `gpt-`, `claude-`, `sonnet`), the words `cursor`, `kdb` and `zpr`, paths (a leading `~/`, `/Users/`, `/home/`, `.scratch/`, `.atl/`, `.cursor/`), and the author marker `BORRAR ANTES DE ENVIAR`. The script builds the `~/` prefix with `printf` so the source contains no quoted tilde. A URL that contains `/home/`, the English word "cursor", or "sonnet" also fails. The template is `docs/examples/nota-de-entrega.md`. Fixtures live in `docs/examples/delivery-note-fixtures/`.
- `scripts/check-repo-paths.sh <markdown> <repo-root>`: exits 0 when every file citation resolves from that root. A citation is inline code or a markdown link target outside a fence, with a file extension that starts with a letter or with a trailing slash. Before the lookup, a trailing line anchor (`:12`, `:12-20`, `#L12`, or `#L12-L20`) is removed. A link target that is `http://`, `https://`, `mailto:`, or only a `#` anchor is skipped. A path containing `*`, `?`, or `[` is a glob and is ignored. A machine-absolute citation (a leading `/`, a leading tilde, or a drive letter) fails without a disk lookup. A citation with a backslash, an empty segment, `.`, or `..` fails as not a repo-root path. Any other citation must exist under `<repo-root>`. The script builds the tilde with `printf` so the source has no quoted tilde. Fixtures live in `docs/examples/repo-path-fixtures/`. `scripts/check.sh` runs the clean fixture and the anchor fixture, and requires the dirty fixtures to name each bad citation and its reason.
- `scripts/check.sh`: the repo's automatic barrier. It fails when a `.cursor/agents/` entry for `zigl`, `zninja`, or `zsensei` is missing, is not a symlink, does not resolve, or does not point at `../../agents/<name>.md`. It fails when `skills/zstack/SKILL.md` lacks `Every Task call to zsensei passes model: claude-opus-5-5-medium.`, and the temp-HOME `link.sh` smoke requires the three plugin agent paths to be regular files matching the repo, with the canary target and a sibling plugin marker unchanged. It also fails when the model matrix, the Opus pin, or the Large `## Modelos` example is missing, and when an Inline without Cursor phrase is missing (`### Inline without Cursor`, `git push --dry-run`, `before coding starts`, and `only the diff` in `skills/zstack/SKILL.md`, plus `independent (no Cursor)` in that file and in `agents/opencode/zstack.md`). It also fails if `--api-key` or `--auth-token` appears under `scripts/`, `hooks/`, or `.githooks/`. The failure names the flag and the file, not the matching line. See `docs/security-cursor-api-key-ps.md`. Runs in `.githooks/pre-commit` (after the main-branch and staged-secret guards) and CI. There is no pre-push hook: CI runs the same check and GitHub protects `main`. It drops `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, and the numbered `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*` pairs so a `git -c` identity on the committing command does not override emails inside fixture repos.
- `scripts/blast-radius-callers.sh <graph> <symbol> [--expect <report>]`: prints every in-module caller of `<symbol>`, including private methods and indirect callers, one `file` and id per line. Callers in other modules are omitted. The changed symbol is not listed as its own caller. The graph is whitespace-separated `symbol` and `edge` rows. Exit 0 when the walk finishes and, with `--expect`, the report matches. Exit 1 when the symbol is unknown or the report does not cover the walk (`in walk only` names callers the report missed). Exit 2 when the arguments or the graph are wrong. Fixtures live in `docs/examples/blast-radius-fixtures/`. `scripts/check.sh` requires the full list and requires a public-only report to fail.
- `scripts/classify-test-failures.sh <head-results> [base-results]`: reads two ledgers of `PASS` or `FAIL`, an id, and an optional detail. A repeated id keeps the last line. It prints a tab-separated `env-known` or `real`, the id, and the detail. A HEAD failure is env-known only when the same id and the same detail fail on the base branch. With no base result, every HEAD failure is real. Failures that exist only on the base branch are omitted. Exit 0 when every HEAD failure is env-known or there are none. Exit 1 when any failure is real. Exit 2 when the arguments or a ledger line are wrong. The exit code is the slice gate. Fixtures live in `docs/examples/test-failure-fixtures/`.
- `scripts/check-commit-order.sh <base> -- <command> [args...]`: checks out each commit in `base..HEAD` (the base commit excluded, oldest first) in a temporary worktree and runs `<command>` there. Exits 0 when every commit's command exits 0, and when the range is empty. Exits 2 when the arguments are wrong. The first non-zero command prints `check-commit-order: FAIL <commit>` and exits non-zero. It does not move `HEAD`, does not set `core.hooksPath`, and does not run `post-checkout`. It does not install a hook. The caller passes a check the repo already defines.
