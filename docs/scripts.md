# Scripts

Scripts carry no comments (decision 20: only issue or RFC links and license lines are allowed). What each one does:

- `scripts/link.sh`: points the user-level Cursor and OpenCode folders at this repo, removes old route-work links that point here, and sets `core.hooksPath` to `.githooks`. It also keeps relative symlinks in `.cursor/agents/` for `zigl`, `zninja`, and `zsensei` (`../../agents/<name>.md`), which Cursor CLI and Cloud Agents load (issue #58). It never replaces a regular file; directories under `~/.agents/skills` are added only when the name is absent. It copies `zigl`, `zninja`, and `zsensei` into `~/.cursor/plugins/local/zstack-agents/agents/` as regular files, after removing a symlink at that destination so the copy does not follow it, and it writes `.cursor-plugin/plugin.json` with name `zstack-agents` and `"agents": "./agents/"`. Matt skills under `~/.agents/skills` are mirrored into Cursor and OpenCode; pstack skills from the Cursor plugin cache go into OpenCode, as `pstack-<name>` when the plain name is taken. `skills/versions` lists one skill name and one rev on each line. `scripts/link.sh` respects a tag or a commit. When a skill has no line, or its rev is `main` or `HEAD`, that skill follows the checkout. To return to main, delete the line or set the rev to `main` or `HEAD`, then run `scripts/link.sh` again. The clone must contain the pinned commits. A depth-1 clone cannot resolve them.
- `scripts/setup-check.sh`: reports whether the local setup resolves, whether the `zgrill`, `zspec`, `ztickets` and `zwayfinder` wrappers and Matt's skills they read are present, whether `tdd` is model-invocable, and the optional MCP env vars (not failures). It fails when a project agent under `.cursor/agents/` is missing, is not a relative symlink to `../../agents/<name>.md`, or does not resolve. It fails when the zstack-agents plugin manifest is missing or lacks `"name": "zstack-agents"` and `"agents": "./agents/"`, and when one of those three plugin agent files is missing, is a symlink, or differs from `agents/<name>.md`. Never prints secret values. For each git repo under the clients root it appends the local artifact lines `.scratch/` and `.atl/` to that repo's `info/exclude` when the exact line is missing, creates the file when it is absent, leaves every other line in place, and is safe to run again. The `local-exclude` line counts repos that have both entries. It does not edit `.gitignore`, add a tracked config file, or install a hook. `scripts/setup-check.sh --help` and a normal run both point at `docs/security-scan.md`. That playbook is the client path (scanner on the developer machine) and the personal path (gitleaks in CI for this repo). A normal run also prints `gitleaks: present` when the binary is on PATH, or a warn when it is missing; that line never fails the script and never installs anything. The script does not install a scanner or a hook.
- `scripts/route-audit.sh [project-filter] [days]`: retro counts from Cursor transcripts under `~/.cursor/projects` (zstack or route-work invoked, zninja or implementer launched, poteto-mode loaded by zninja, inline edits with and without a stated reason, delegated runs by `zstack delegated: <role>`, and orchestrator test fixes with `launched: no (orchestrator-fix: <reason>)`). Writes under `.scratch/` count as reports, not code edits. Rules: `docs/delegated-runs.md`. Exits 1 on the failures listed in `docs/architecture.md`. The file lives in `skills/zstack/scripts/route-audit.sh`, so `scripts/link.sh` exposes it as `~/.cursor/skills/zstack/scripts/route-audit.sh` (and under `~/.config/opencode/skills/zstack/`), the path zStack runs; `scripts/route-audit.sh` is a shim that runs that file.
- `scripts/cursor-delegate.sh --workspace <dir> --prompt <file> --out <file> --role impl|fix|review --size Small|Medium|Large|Critical --verifiable full|partial --reason <text> [--model <slug>] [--approval sandbox|auto-review] [--idle <seconds>] [--max <seconds>]`: launches a headless Cursor CLI run (`agent -p --trust`). It adds `--sandbox enabled` by default, or `--auto-review` with `--approval auto-review`, so the run can execute commands while `~/.cursor/cli-config.json` keeps a narrow allowlist. It never passes `--force` and rejects a `-fast` model unless `DELEGATE_ALLOW_FAST=1`. The prompt sent starts with the canonical line `zstack: <Size>, <full|partial> verifiable — delegated <role>: <reason>` and `zstack delegated: <role>`, then `docs/delegated-run-rules.md`, a `---` line, then the prompt file. Output is `stream-json` in `<out>`, stderr in `<out>.err`, and `<out>.meta` records start, model, approval, limits, exit, and end; with `jq` on PATH the final report also lands in `<out>.txt`. A watchdog kills the agent and its child processes when `<out>` stops growing for `--idle` seconds (default 900, `DELEGATE_IDLE`; 0 turns it off) or after `--max` seconds (default 0, off; `DELEGATE_MAX`), writes `exit=killed(...)` and exits 124. `AGENT_BIN` overrides the binary for tests. Limits and the orchestrator side: `docs/delegated-runs.md`.
- `scripts/retro-log.sh`: records each applied retro change in `.scratch/retro-log.tsv`. Columns are id, date, state, cksum, bytes, error, and path. `begin --path <rel>` saves the current bytes under `.scratch/retro-open/<id>`, or writes a `<id>.missing` marker when the path is absent, and prints the new id. `seal <id> --error <text>` requires that open id, rejects an empty error, records the POSIX `cksum` of the file, and appends a pendiente row. A missing file at seal time stores the fingerprint word `missing` and byte count 0. Seal moves the saved bytes to `.scratch/retro-snapshots/<id>`. `pending` prints pendiente rows with no header and exits 0 when none exist. `confirm <id>` moves a pendiente row to confirmado, deletes the snapshot, and prints the id. A second confirm exits non-zero and leaves the row unchanged. `revert <id>` moves a pendiente row to revertido and prints the id. It prints `restored` and copies the saved bytes back when the current fingerprint still matches, or deletes the path when the retro added the file. It prints `marked-only` and does not change the tree when the snapshot is gone. A different fingerprint prints `dirty`, exits 3, and leaves the row pendiente. `revert --force <id>` restores even when the fingerprint differs. Exit 2 is usage, a bad field, or a rejected path. Rejected paths include an absolute path, a leading tilde, a backslash, an empty segment, `.`, `..`, and any path under `.scratch`. A tab or a newline in any field is also exit 2. `RETRO_ROOT` selects the worktree and defaults to `git rev-parse --show-toplevel`, or to the current directory when that fails. `RETRO_DATE` sets the row date as `YYYY-MM-DD`.
- `scripts/mcp-gitlab.sh`, `scripts/mcp-postgres.sh`: start those MCP servers; the token or URL stays in the environment.
- `scripts/check-draft-sections.sh qa-inputs <draft>`: exits 1 when a client QA inputs draft lacks `## Funcionalidades modificadas`, `## Dónde se gatillan`, `## Referencia al código`, `## Fuera de alcance`, or `## Casos de QA sugeridos`. The template is `docs/examples/insumos-qa.md`.
- `scripts/check-delivery-note.sh <note>`: exits 0 when a client delivery note has no internal mention, and exits 1 when it does. Patterns, case-insensitive: tool and agent names (`zstack`, `zninja`, `zsensei`, `zigl`, `zgrill`, `zspec`, `ztickets`, `zwayfinder`, `zretro`, `poteto-mode`, `poteto`, `opencode`, `obsidian`, `agent-workflow`), model prefixes (`grok-`, `gpt-`, `claude-`, `sonnet`), the words `cursor`, `kdb` and `zpr`, paths (a leading `~/`, `/Users/`, `/home/`, `.scratch/`, `.atl/`, `.cursor/`), and the author marker `BORRAR ANTES DE ENVIAR`. The script builds the `~/` prefix with `printf` so the source contains no quoted tilde. A URL that contains `/home/`, the English word "cursor", or "sonnet" also fails. The template is `docs/examples/nota-de-entrega.md`. Fixtures live in `docs/examples/delivery-note-fixtures/`.
- `scripts/check-repo-paths.sh <markdown> <repo-root>`: exits 0 when every file citation resolves from that root. A citation is inline code or a markdown link target outside a fence, with a file extension that starts with a letter or with a trailing slash. A span with no `/` whose extension, the text after the last dot, starts with an uppercase letter is a dotted identifier and is ignored (`System.Text.Json`). `OnlyName.cs` and `appsettings.Development.json` stay citations. A fence opens on a run of backticks or tildes, length at least 3. Optional leading whitespace is skipped, and so is a leading blockquote prefix: optional whitespace, then one or more `>` each optionally followed by a space. A fence inside a blockquote or an Obsidian callout is a fence, and citations inside it are ignored. A line whose text after that opening run contains another run of the same character, at least as long as the opener, is an inline span, not a fence. The citation in that span is checked. The opening line may carry an info string. A closer is the same character, at least as long as the opening run, with only whitespace after the run. A shorter run or the other character does not close the fence. Content inside the fence is ignored. An unclosed fence fails with `fail repo-paths: unclosed fence:`. Before the lookup, a trailing line anchor (`:12`, `:12-20`, `#L12`, or `#L12-L20`) is removed. A link target that is `http://`, `https://`, `mailto:`, or only a `#` anchor is skipped. A path containing `*`, `?`, or `[` is a glob and is ignored. A machine-absolute citation (a leading `/`, a leading tilde, or a drive letter) fails without a disk lookup. A citation with a backslash, an empty segment, `.`, or `..` fails as not a repo-root path. Any other citation must exist under `<repo-root>`. The script builds the tilde with `printf` so the source has no quoted tilde. Fixtures live in `docs/examples/repo-path-fixtures/`. `scripts/check.sh` runs the clean fixture and the anchor fixture, and requires the dirty fixtures to name each bad citation and its reason. The file lives in `skills/zspec/scripts/check-repo-paths.sh`, so `scripts/link.sh` exposes it as `~/.cursor/skills/zspec/scripts/check-repo-paths.sh` (and under `~/.config/opencode/skills/zspec/`), the path zspec and to-techspec run; `scripts/check-repo-paths.sh` is a shim that runs that file.
- `scripts/check-topic-repos.sh --kdb <file> --draft <file> [--present <dir> ...]`: exits 0 when the KDB has no `topics` fence, when a named topic's repo is in `--present`, or when every draft line that names a topic word is `Qn. … repo-ausente: <repo>`. Otherwise exits 1 with `fail topic <tema>: concluded without repo <repo>`. The fence is tab-separated `tema`, comma-separated words, and repo name. A paste-ready lesson is `docs/examples/kdb-lesson-topics.md`.
- `scripts/check-client-surface.sh <deliverable> [private]`: exits 0 when the deliverable has no `INTERNO:` line, no `BEGIN OPENSSH` or `BEGIN PRIVATE KEY` block, and no connection string. A connection string is a database or broker URI (`postgres://`, `postgresql://`, `mysql://`, `mariadb://`, `mongodb://`, `mongodb+srv://`, `redis://`, `rediss://`, `amqp://`, `amqps://`, `mssql://`, `sqlserver://`, `oracle://`, `neo4j://`, `bolt://`, `couchbase://`, `cassandra://`, `jdbc:postgresql:`, `jdbc:mysql:`, `jdbc:mariadb:`, `jdbc:oracle:`, `jdbc:sqlserver:`, `jdbc:jtds:`), userinfo on any scheme (`scheme://user:secret@host`), or a `password=` / `pwd=` assignment on the same line as `host=`, `server=`, `data source=`, `user id=`, `user=`, `username=`, or `uid=`. A plain `http://`, `https://`, or `mailto:` URL with no userinfo stays. The word password with no `=` stays. `INTERNO:` lines and key blocks belong in the private file (default `.scratch/privado.md`, even if the body is only `ninguno`). The script rejects connection strings in the deliverable. A missing private file or a marked line in the deliverable exits 1 with `fail surface:`. A connection string prints `fail surface: connection string in the deliverable` and does not print the matching line.
- `scripts/evidence-probe.sh --repo <dir> --token <text>`: prints `config: found <path>` or `config: absent` after looking in `*values*.yaml`, `*values*.yml`, `Chart.yaml`, and files under `deploy/` or `helm/`, and prints `history: found <subject>` or `history: absent` from `git log -S`.
- `scripts/check-claims.sh --repo <dir> --draft <file>`: exits 1 with `fail claims: add a claims fence` when the draft has no `claims` fence. A backtick token marked `ausente` while the probe found it in values exits 1 with `fail evidence: <token> is in deploy values`. A `bug` or `defecto` claim about a backtick token must quote the `git log -S` subject on its own line or as a citation whose backticks, double quotes, or single quotes sit against that subject. A substring inside a sentence does not count. Otherwise the check exits 1 with `fail evidence: quote the git log -S subject`.
- `scripts/check-unmerged-branches.sh --repo <dir> --draft <file> [--base <ref>]`: each local branch not merged into `--base` (default `main`) must appear in the draft as a full token, not a substring, or the check exits 1 with `fail branches: <name> not named`. When none are unmerged, the draft needs the exact line `ramas-fuera-de-base: ninguna`.
- `scripts/check.sh`: the repo's automatic barrier. It fails when a `.cursor/agents/` entry for `zigl`, `zninja`, or `zsensei` is missing, is not a symlink, does not resolve, or does not point at `../../agents/<name>.md`. It fails when `skills/zstack/SKILL.md` lacks `Every Task call to zsensei passes model: claude-opus-5-5-medium.`, and the temp-HOME `link.sh` smoke requires the three plugin agent paths to be regular files matching the repo, with the canary target and a sibling plugin marker unchanged. It also fails when the model matrix, the Opus pin, or the Large `## Modelos` example is missing, and when an Inline without Cursor phrase is missing (`### Inline without Cursor`, `git push --dry-run`, `before coding starts`, and `only the diff` in `skills/zstack/SKILL.md`, plus `independent (no Cursor)` in that file and in `agents/opencode/zstack.md`). It also fails if `--api-key` or `--auth-token` appears under `scripts/`, `hooks/`, or `.githooks/`. The failure names the flag and the file, not the matching line. See `docs/security-cursor-api-key-ps.md`. Runs in `.githooks/pre-commit` (after the main-branch and staged-secret guards) and CI. There is no pre-push hook: CI runs the same check and GitHub protects `main`. It drops `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, and the numbered `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*` pairs so a `git -c` identity on the committing command does not override emails inside fixture repos.
- `scripts/blast-radius-callers.sh <graph> <symbol> [--expect <report>]`: prints every in-module caller of `<symbol>`, including private methods and indirect callers, one `file` and id per line. Callers in other modules are omitted. The changed symbol is not listed as its own caller. The graph is whitespace-separated `symbol` and `edge` rows. Exit 0 when the walk finishes and, with `--expect`, the report matches. Exit 1 when the symbol is unknown or the report does not cover the walk (`in walk only` names callers the report missed). Exit 2 when the arguments or the graph are wrong. Fixtures live in `docs/examples/blast-radius-fixtures/`. `scripts/check.sh` requires the full list and requires a public-only report to fail.
- `scripts/classify-test-failures.sh <head-results> [base-results]`: reads two ledgers of `PASS` or `FAIL`, an id, and an optional detail. A repeated id keeps the last line. It prints a tab-separated `env-known` or `real`, the id, and the detail. A HEAD failure is env-known only when the same id and the same detail fail on the base branch. With no base result, every HEAD failure is real. Failures that exist only on the base branch are omitted. Exit 0 when every HEAD failure is env-known or there are none. Exit 1 when any failure is real. Exit 2 when the arguments or a ledger line are wrong. The exit code is the slice gate. Fixtures live in `docs/examples/test-failure-fixtures/`.
- `scripts/check-commit-order.sh <base> -- <command> [args...]`: checks out each commit in `base..HEAD` (the base commit excluded, oldest first) in a temporary worktree and runs `<command>` there. Exits 0 when every commit's command exits 0, and when the range is empty. Exits 2 when the arguments are wrong. The first non-zero command prints `check-commit-order: FAIL <commit>` and exits non-zero. It does not move `HEAD`, does not set `core.hooksPath`, and does not run `post-checkout`. It does not install a hook. The caller passes a check the repo already defines.
- `scripts/sonar-diff-issues.sh <base> <issues.json | --fetch <project-key>>`: prints open SonarQube issues that sit on lines `<base>...HEAD` added or changed, one `path:line`, severity, rule and message per line. `--fetch` reads them from `SONAR_HOST_URL` (default `http://localhost:9000`) with `SONAR_TOKEN` from the environment, passed to curl on stdin so it never shows on the command line. Exit 0 none, 1 some, 2 usage or bad input, 3 no instance answered. Issues without a line and issues on untouched lines are ignored. Playbook: `docs/security-scan.md`.
- `scripts/check-remote-tests.sh <repo-root>`: lists test files that may reach a remote service, one `path` and reason per line: `remote-url` (a URL literal whose host is not local: localhost, loopback, `example.*`, `.test`, `.invalid`, `.localhost`) or `configured-http` (an HTTP client plus a configuration read in the same file). Skips `.git`, `node_modules`, `bin`, `obj`, `dist` and `.scratch`. Exit 0 none, 1 some, 2 usage. zstack gates exclude the listed files.
- `scripts/check-required-claims.sh <draft.md>`: fails each line outside a fence that calls a field, column, property, parameter or attribute required, mandatory, obligatorio or not null without `fuente:` on the same line. Exit 0 clean, 1 unsourced claim, 2 usage.
- `scripts/check-export-package.sh <dir>`: checks every `*.json` in a package before it is shared. Fails a secret-like key (token, password, secret, api key, authorization, cookie, session and variants) with a set value, a Postman-style `key`/`value` pair of that kind, and a JWT-shaped value anywhere. `{{name}}` placeholders pass. Runs `gitleaks dir --redact` when gitleaks is on PATH. Exit 0 clean, 1 finding, 2 usage or missing jq.
- `scripts/mode-for.sh <path>`: prints `mode: <plan-only|ask-first|accept-edits> (<source>)` for a worktree. A client table in `clients.toml` (`ZSTACK_CLIENTS_TOML` for a fixture) whose `root` is the longest prefix of the path gives its `mode`, or `ask-first` when unset. Any other path under the clients root (`CLIENTS_ROOT`, then `clients_root`, then `$HOME/Clients`) is `ask-first`; everything else is `accept-edits`. `ZSTACK_MODE` applies only when it is stricter. Exit 2 is usage, a missing directory, or an unknown mode.
- `hooks/client-guard/push-checks <base> <head> [branch]`: checks one push range for config paths, added lines with a RUT or a disallowed email, a branch name without a ticket key, and config paths on a branch that ends in `-main`. An empty `base` is the commits on `head` that are not on a remote. Exit 1 on a `fail` line. The exact value `1` warns instead for `CLIENT_ALLOW_CONFIG`, `CLIENT_ALLOW_SENSITIVE`, `CLIENT_ALLOW_BRANCH`, and `CLIENT_ALLOW_MAIN_CONFIG`. `CLIENT_SKIP_GITLEAKS=1` skips gitleaks. A finding prints the path and a count, never the matched value.
- `scripts/revert-rate.sh [-C <repo>] [--since <date>] [--until <date>] [--branch <ref>]`: prints the revert rate for the first-parent commits on a branch. Defaults are the repo `.`, since `30 days ago`, no until bound, and the branch `origin/HEAD` when `git rev-parse --verify --quiet` resolves that ref locally without a network call, otherwise `HEAD`. Every first-parent commit counts as one change, including a merge and a squash. A revert is a commit whose subject starts with `Revert "`, or whose body contains the marker `This reverts commit ` with its trailing space. A commit that matches both is one revert. A revert of a revert counts. The script reads local git history only and filters with the committer dates already stored on the commits. Human stdout is `changes N, reverts R, rate P%`, then one line per revert, newest first, as a 7-character sha, a space, and the subject. The last line is `revert-rate changes=N reverts=R rate=P`. P has one decimal. When N is 0, P is 0.0. Success exits 0, including a nonzero rate. An unborn branch is zero changes and exits 0. Exit 2 is a bad argument, a missing path, a path that is not a git repo, a `--branch` that does not resolve, or a date git rejects.
